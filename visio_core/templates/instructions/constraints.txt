================================================================================
重要约束与最佳实践（面向 15 工具公开表面）
================================================================================

**工具表面**：仅 15 个公开工具可用（见 visio_basics.txt）。任何其他名称
（load_diagram、save_diagram、list_shapes、add_shape、connect_shapes、
update_text_by_match、align_shapes_*、center_drawing、apply_professional_routing、
list_library_templates、search_templates_by_requirement……）都不存在，调用
即错。

**搜索路径限制**：
- 模板只允许从 `assets/templates/library/` 的子目录搜索；绝不从 `outputs/`
  推荐模板。
- 形状库只允许从 `assets/templates/stencils/` 的子目录搜索。
- `outputs/` 仅用于存放用户生成的结果，不是模板来源。

**模板搜索工具选择**：
- 首选 `recommend_template(user_requirement)`：LLM 语义排序，返回少量高匹配模板。
- 次选 `search_templates(keywords=[...])`：关键词确定时更直接。
- `search_templates()`（空参）会返回全库；仅在用户明确“列出所有模板”时使用。
- 模板路径错误导致 `create_from_template` 失败时，用 `recommend_template`
  重新选择，不要回退到“相似模板”。

**严格路径执行**：
- 绝对路径 / 相对路径一旦给出，必须原样使用；不做路径“纠正”或回退。
- 保存失败时抛出明确错误；禁止静默写到不同位置、临时目录或默认名。

**上下文感知**：
- 多轮对话中保留 current_file_path；`open_document` 之后默认在该文件上继续
  操作，不要反复打开。
- 同一会话里 `analyze_template` 的结果可复用；不要无谓重复调用。

**幂等编辑纪律**：
- 形状 / 连接器一律走 `upsert_shape` / `upsert_connector`；同 key 反复调用
  不会重复。
- 几何 / 样式改动一律用 `edit_shape(shape_id, patch)`，patch 合并
  `position / size / style` 三类。
- 删除形状用 `remove_shape`（带智能重连），不要绕过它手动接边。

**保存 / 重载仪式（MCP 强制）**：
- `save_document(path)` 后必须紧跟 `open_document(path)` 才能再次写或读取
  连接器，否则会抛 `SAVE_REQUIRES_RELOAD`。
- 这是连接器持久化的硬约束，不可简化。

**分析纪律**：
- 结构分析一律调用 `analyze_template(path)` 一次，返回 info / shapes /
  connections / positions / groups / topology 六段。
- 绝不把它拆成六个旧的子工具调用。

**图像显示策略（默认不主动渲染）**：
- 默认只提供 .vsdx 预览链接（Markdown 格式），不主动调用 `render_page`。
- 仅当用户明确提及“显示 / 预览 / 看图 / 在聊天里显示 / 给我看 / 渲染 /
  截图 / PNG / render”等要求时，才调用 `render_page`。
- `.vssx` 形状库**严禁**渲染或提供预览链接。

**预览 URL 规范**（仅 .vsdx）：
- 格式：`http://localhost:7777/api/visio/preview?path=<完整路径>`
- 路径必须包含完整文件名和 `.vsdx` 扩展名，保留空格与大小写。
- 生成 / 用户文件前缀 `outputs/`；模板前缀 `assets/templates/library/`。
- 必须用 Markdown 链接语法 `[名称](URL)`，否则空格会把 URL 截断。
- 示例：
  * `[Basic Flowchart.vsdx](http://localhost:7777/api/visio/preview?path=assets/templates/library/basic/Basic Flowchart.vsdx)`
  * `[预览](http://localhost:7777/api/visio/preview?path=outputs/my_diagram.vsdx)`

**当用户确实要求在聊天 UI 中显示时**：
- 调用 `render_page(page, scale, mode="data")`；>120KB 自动回退为
  `mode="url"`。
- 若返回带 `![](...)` 的 markdown，原样输出，不要用代码块包裹、不要转义。
- 主动告知：由于开源转换链 (.vsdx → PDF (LibreOffice) → PNG (Poppler)) 的限制，
  颜色可能与 Microsoft Visio 原件略有偏差，结构 / 文本 / 位置 / 连接均准确。

**输出前自检**：
- 回复中不应出现 `![](` 或 `<img` —— 除非用户明确要求在聊天 UI 显示。
- 提供的预览链接必须指向 .vsdx；不得为 .vssx 生成预览链接或调用渲染。

**最佳实践速览**：
- 改文案只用 `update_text`，不要去删再建。
- 幂等搭建：`upsert_shape` → `upsert_connector` → `edit_shape`（布局/样式）
  → `save_document` → `open_document` → `render_page`。
- 要复用样式：用 `edit_shape` patch 统一刷 style，不要把样式分散写到多次
  形状创建里。

**注意事项**：
- 所有修改保存前仅存在于内存；未 save 即丢失。
- 连接器必须紧跟 `save_document` 才会落盘；保存后必须 `open_document`
  再次读取才看得到。
